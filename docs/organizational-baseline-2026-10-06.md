# 現行DBの組織知表示基準（段階①）

2026-10-06、OK-Core `develop_kawa` の現在の作業ツリーと `ok_core` DB（ローカルMAMP）を対象に確認した。Forestからの新API受信や旧Forest DBの移行は、この段階の対象外。

## DBの読み取り結果

| 対象 | 現状 |
| --- | --- |
| グループ100のKF | experience 10件、discussion 9件。マップ・連結化一覧とも計19件 |
| グループ100の組織知 | 有効ノード19件、リンク表の参照25件（experience 12件、discussion 13件） |
| 参照できるリンク | experience 10件、discussion 13件。ノード419のexperience参照 `11142` と `11145` は現在グループ100に共有されていない |
| 未割当の組織知 | 5件。ルート `1`、`2`、`3`、子 `113`、`114`。子113には `discussion:1` のリンクがあるが、現行のグループ100には属さない |
| 同じ数値IDを持つ異種KF | `11145`、`11147`、`11154`、`11155` の4組。画面上は `experience:ID` / `discussion:ID` として区別する |
| 全体の保存件数 | 有効組織知24件、リンク26件、KF配置0件、議論履歴0件 |

未割当5件は旧データの可能性があるが、どの組織へ属するかをDBだけでは断定できない。段階①ではグループ100へ自動割当せず、後のツリー整理で所有先を決める。ノード419の旧リンクもDBから削除していない。表示・詳細取得では現在共有されている2件 (`experience:11164` / `experience:11168`) だけを返す。

## この段階で揃えた取得経路

- KF一覧と組織知ツリーのセッション開始をトップページと同じ `OKCORESESSID` に統一した。
- グループの取得処理を共通化し、マップ・組織知ツリー・詳細表示で、ログインと有効なグループ所属を確認する。権限外の明示指定は403、未ログインは401を返す。
- 組織知ツリーと詳細には、現在そのグループで参照できるKFだけを含める。別グループや未割当のノード・KF本文を表示しない。
- グループ切替中の古いツリー・詳細応答を破棄し、開いていた詳細画面を閉じる。マップの取得も現在選択中のグループを確認する。
- Forest側に残るJSONの二重パースは移さず、OK-Coreの `dataType: 'json'` とオブジェクト処理を維持した。

## 検証結果

PHP 8.2で変更した5ファイルを構文検査し、変更した2つのJSファイルも構文解析した。現行DBを使い、各PHP取得処理を認証済み・未認証・権限外で実行した。隔離したローカルPHPサーバーではテスト用に既存の所属ユーザーのセッションを注入し、ヘッドレスChromeでトップページから連結化タブを開いた。実際のSSOログイン操作は今回のブラウザ試験に含めていない。

| ケース | 結果 |
| --- | --- |
| グループ100のマップ・KF一覧 | HTTP 200、どちらもexperience 10件＋discussion 9件 |
| グループ100の組織知ツリー | HTTP 200、19件、返却された所属IDは100のみ |
| ノード419の詳細 | HTTP 200、現在共有中のexperience KF 2件のみ |
| 未割当ノード113の詳細 | HTTP 404 |
| 権限外グループ101 | マップ・一覧・ツリーともHTTP 403、詳細は表示しない |
| 未ログイン | KF一覧・ツリーともHTTP 401 |
| Chromeで連結化タブを開く | KFカード19件、組織知ノード19件、記録したJavaScript例外0件 |
| Chromeで権限外グループ101へ強制切替 | KFカード0件、組織知ノード0件、記録したJavaScript例外0件 |

確認後のDB件数は有効組織知24件・リンク26件・配置0件・履歴0件で変化していない。現行DBで有効な所属先はグループ100だけなので、複数の許可済みグループ間の切替は未検証。今後のグループ追加時に同じ回帰条件で確認する。
